## Additional decisions made in M0

| ID | Decision | Choice | Reason |
|----|----------|--------|--------|
| D9 | Entry point | **No `Main`.** Top-level statements of a `Program` run in order, after module initialisation | Both reference languages work this way; simplest mental model. |
| D10 | Case sensitivity | **Case-insensitive** keywords and identifiers; the compiler preserves the first-declared spelling in diagnostics and emitted symbols | Matches both reference languages' feel. Emitted pic-as symbols are normalised (pic-as is case-sensitive). |
| D11 | Operators on booleans vs integers | `And/Or/Xor/Not` are logical on Boolean operands, bitwise on integer operands; **mixing the two is an error** | Removes a classic source of bugs without changing common code. |
| D12 | Narrowing assignment | Constant that does not fit → **error**; non-constant narrowing → **warning** (error under `#option Strict = true`) | Safe by default, convenient when wanted. |
| D13 | Recursion | **Rejected at compile time** by default; allowed only for `Reentrant` routines | Static frames need a known call graph. |
| D14 | Line continuation | A line ending in ` _` (space + underscore) continues on the next line | Identifiers may start with `_`, so the space is required. |
| D16 | Expression evaluation width | **Context-width rule**: an arithmetic expression is evaluated at the width of the widest of its operands and its assignment target; never wider unless converted explicitly | Efficiency priority (PLAN §7A.2): `Word = Byte * Byte` is one hardware multiply, `Byte = Byte + Byte` stays 8-bit. Precisely specified in `LANGUAGE.md` §5.3. |
| D17 | Optimisation scope | **Whole-program compilation**; an `-O0` reference build is always available and is the oracle for differential testing | Enables dead-code removal, single-call inlining, frame overlay, stack proof (PLAN §7A.1). |
| D18 | Efficiency is gated by measurement | Benchmark harness (size via map file, cycles via MDB) built in **M4**; XC8 `-Os`/`-O2` baselines; targets calibrated from real numbers at M4, enforced from M5 | PLAN §7A.4. |
| D19 | Internal integer widths | **8, 16, 24 and 32 bits** are all first-class in the IR; the *language* types stay 8/16/32 (24-bit appears only as a compiler-chosen width after range analysis) | 24-bit is cheaper than 32-bit on an 8-bit core (to be re-measured in M4). |
| D15 | Vendor material | Manuals kept in `reference/` (git-ignored); nothing copied from vendor libraries or data files | PLAN §2. |

## Decisions made in M4 (back end)

| ID | Decision | Choice | Reason |
|----|----------|--------|--------|
| D28 | Calling convention | Arguments stored straight into the callee's static frame; result read from the callee's `Result` variable; nothing preserved across calls | With static frames the caller knows every address; simplest correct form, measured against alternatives in M5. Finalises D4 for non-reentrant code. |
| D29 | Data placement | The compiler assigns all data addresses (`equ`), hottest first into the Access Bank; pic-as places only code | Exact bank-select decisions at compile time; usage counts drive placement (PLAN §7A.3 #3). |
| D30 | Code placement | One absolute psect from address 0; no reset `goto` while there are no interrupts | Smallest; vectors are added with interrupts in M6. |
| D31 | Division | Truncates toward zero; `Mod` takes the dividend's sign; divide by zero gives an all-ones quotient and the dividend as remainder | Matches C and what the restoring helper produces for free; no trap code. Unsigned division/mod by a power of two is a shift/mask. |
| D32 | Port writes | A store to `PORTx` is emitted as a store to `LATx` | Avoids read-modify-write on the pins; reads are unchanged. |
| D33 | `For` loop | Limit evaluated once; constant step only (variable step is `E-BACKEND`); after a loop that ran the variable holds the last value it took (the limit for step ±1), and the counter never steps past the limit, so a `Byte` loop to 255 terminates | Needed for a correct count-down/`DECFSZ` form in M5. Post-loop value was unspecified; this is now the rule. |
| D34 | Signed multi-byte compare | Both top bytes are biased by 0x80 and compared unsigned; the overflow flag of a multi-byte subtract is not used | The simulator's `SUBWFB` overflow flag disagreed with the textbook value, and the data sheet only says OV is affected (DS40002043F p.674). The carry chain is unambiguous. |
| D35 | Unsupported constructs | Reported as `E-BACKEND` at the use, never miscompiled: structures, `Bit` by reference, `ByRefConst` arrays, `@`, `Abs/Min/Max`, events, multi-bit register fields, 3-byte registers | Scheduled for M5 (data) and M6 (interrupts). |
| D36 | Counted `For` loops | A `For` with constant bounds and step and at most 255 passes counts a hidden Byte down with `DECFSZ`/`DCFSNZ`; the variable is kept current unless the body never mentions it | Keeps D33 semantics (`Break`/`Return`/callee reads see the right value). Refused when the body writes the variable, takes its address, has raw `Asm`, or (global variable) calls anything. |
| D37 | Frame overlay and locals | Two routines share RAM when neither can reach the other in the call graph (the main program and an interrupt handler never share). A local variable and `Result` are therefore **zero on every entry** unless the body provably assigns them first; start-up clears only globals | Overlaid storage holds whatever another routine left, so the old "zeroed once at start-up, kept between calls" behaviour cannot survive. Zero on entry is the same rule for every routine whether or not its frame happens to overlay. Large local arrays pay a clear per call. |
| D38 | Optimiser switch and the oracle | `-O0` turns off the peephole pass and the in-place read-modify-write forms; overlay and zero-on-entry stay on because they are language semantics, not optimisations | The simulator suite runs both builds and the results must agree (PLAN §7A.1 rule 7). |
| D39 | Peephole scope | One pass over the item list, local to straight runs, with `Fence` items at statement ends marking `WREG` and `__A`..`__D` dead; delay code is fenced off (`Keep`) because its cycle count is exact | Facts come only from the instruction stream; anything unknown ends the run. Reads of device registers are never removed or merged. |

## Decisions made in M6 (interrupts)

| ID | Decision | Choice | Reason |
|----|----------|--------|--------|
| D40 | Interrupt modes and vectors | No handler has a priority: `IPEN = 0`, the one handler sits right at `0x0008` and returns with `RETFIE, FAST` (plain `RETFIE` after a software save when `ISR_SHADOW = false`). Any priority given: `IPEN = 1` (set at start-up), `0x0008` and `0x0018` hold a jump to the `ipHigh` / `ipLow` handler, an unserved vector spins. With any handler, `0x0000` is a branch to the start-up code | Fixed vectors only on this part `[DS40002043F p.193]`. A spinning vector is deterministic and visible under a debugger; a bare `RETFIE` would re-take a source nobody clears forever. |
| D41 | `Enable` / `Disable` | They only touch the global bits of `INTCON`: `Enable` sets GIEL/PEIE then GIEH/GIE (a high handler: GIEH only); `Disable` of a low handler clears GIEL, otherwise clears GIE/GIEH and re-checks it reads back clear. The peripheral enables (`PIEx`) and priorities (`IPRx`, which reset to **high**) are the program's to set | `[DS40002043F p.198, p.215–217]`. The handler name is not tied to a peripheral (language §8), so the compiler cannot know which `PIEx`/`IPRx` bit belongs to it. With `IPEN = 1`, GIEH = 0 disables **every** interrupt, so enabling a low handler also sets GIEH. `RETFIE` sets the global bit again, so `Disable` inside a handler does not outlast it. |
| D42 | Context save | A handler saves, in its own static area, exactly the compiler registers its code touches (`FSR0..2`, `TBLPTR`, `TABLAT`, `PRODL/H`, the used bytes of `__A`..`__D`, found by scanning its emitted code and the shared helpers it calls). `WREG`, `STATUS`, `BSR` use the hardware shadow copy except for a low handler when both priorities exist (`#option ISR_SHADOW = false` forces software save everywhere). All copies are `MOVFF`, which needs no bank and no flags | `[DS40002043F p.112]`: a high interrupt overwrites the shadow copy. Saving only what is used keeps a small handler to a few instructions. |
| D43 | `Save … Restore` | Copies the listed variables, routine frames (and everything those call) and, for `0`, all compiler registers into a private area before the block and back after it, also on `Exit`/`Break`/`Continue`. Inside a handler every routine called in the block has its frame and registers saved even if not listed. `Goto` and labels inside `Save` are `E-BACKEND` | A callee's frame may overlay main-line storage (D37); saving whole address ranges makes that safe whichever routines share them. A jump out would skip the restore. |
| D44 | Handler frames | A handler is never independent of any routine in the overlay analysis, so its locals and temporaries never share an address; they are zero on every entry like any local | The handler can run at any moment. |
| D45 | Atomicity | None is provided. Reading or writing a variable wider than a byte that a handler also uses can see a half-updated value; the program must disable the interrupt around such accesses | Matches the reference language; an `Atomic` form can come later. |

## Decisions made after M8 (array completion)

| ID | Decision | Choice | Reason |
|----|----------|--------|--------|
| D47 | `Bit`/`Boolean` arrays | **Packed eight to a byte when the array is only ever indexed (`a(i)`); one byte per element when it is used as a whole** (passed `ByRef`, copied, cleared, given an initialiser, or a structure field). Decided per array by `sema.rs` (`Analysis::unpackable`); `Bound(a)` does not count as a whole use. `types.rs::size_bytes` stays one byte per element; the lowerer packs the `Dim`med variable (`Lowerer::packed`) | A constant index folds to `bsf`/`bcf`/`btfsc` on a fixed byte and bit, as cheap as a `Bit` variable. A run-time index needs a shift and mask (`Place::dbit`), which is the cost of packing, so it is paid only where the RAM saving is available. Arrays that must be addressable as bytes (`ByRef`, initialisers, copies, structure fields) keep the 8x RAM cost rather than make every access to them dearer. Global RAM is checked with the packed size. Neighbouring elements share a byte, so a write through a run-time index is a read-modify-write; when the program declares any `Interrupt` it runs with the global interrupt enable off (`Lowerer::bit_store`: INTCON saved, bit 7 cleared, write, bit 7 set again only if it was set) so a handler writing another element cannot be overwritten. A constant index is a single bit instruction and needs no guard. The same guard covers every other run-time bit read-modify-write (bit fields reached through `ByRef` or a run-time index). Reversible: the decision is `Analysis::unpackable`. |
| D48 | `Const` arrays | Kept in program memory (`Base::Flash`, label `__CA<n>`, little-endian elements) and read with `TBLRD*+`; a constant index folds to a literal. Passed to a `ByRefConst` parameter they are copied once at start-up to a RAM buffer, like string literals (D-strings) | One access path in the callee. Costs RAM only for tables that are actually passed by reference. |
| D49 | Array parameter length | A `ByRef`/`ByRefConst` array parameter is the 16-bit address; when its routine calls `Bound(a)` it also holds the 16-bit element count in the next two bytes, passed by every caller. Callers of routines that never use `Bound` pass nothing (`strip_unused_lengths`) | `Bound` of a parameter needs the length at run time; the cost is paid only by routines that ask for it. |
| D50 | Array initialisers | Zero storage is already guaranteed (start-up clears globals, entry clears locals), so only non-zero values are written: stored one by one up to 8 bytes, otherwise copied from a program-memory table. Whole-array copies and clears of any size up to 65535 bytes work (chunks of 255) | Smallest code for the common cases. |

## Decisions made after M8 (Float)

| ID | Decision | Choice | Reason |
|----|----------|--------|--------|
| D51 | Float implementation | A `Float` is stored as its binary32 pattern (4 bytes, `nat` = 32 bits unsigned), so loads, stores, copies, arrays, parameters and results are the LongWord paths. The arithmetic is **written in the language itself**: `lib/floatlib.bas` (`FAdd FSub FMul FDiv`, `FEq FNe FLt FLe FGt FGe`, `FFromLong FFromULong FToLong`). The loader includes it when a source file contains the word `Float`; the lowerer turns each Float operation into a call to it (`Lowerer::flt_call`), and only the routines used are linked. Negation and `Abs` flip and clear the sign bit inline. Integers mixed with a Float are converted at compile time when constant and by `FFromLong`/`FFromULong` otherwise. `Byte(f)` etc. truncate toward zero through `FToLong` (saturating at the LongInt limits, NaN gives 0), then cut to the target width. Round to nearest even; infinities and NaN are produced and propagated; **denormals are not supported** (exponent 0 reads as zero, a too-small result becomes a signed zero). Float work **directly in an interrupt handler is `E-ISR-CALL`** (the Float routines' static frames would be shared with the main program); put it in a routine and call that inside `Save(…) … Restore`, which saves the routine's frame and the Float routines it calls. Not provided yet: `Float` in `Select`, as a `For` variable or with `Inc`/`Dec` (all rejected by the front end), `Str`/`Print` of a Float, `Sqr` and the other functions | One implementation to verify on the simulator against the host's exact float32 results (about 2,500 bit-exact checks, `tests/exec/lib_floatlib*.bas`), no new assembly, and the linker keeps a program that does not use a routine free of it. The cost is code size: a hand-written assembly version would be smaller (FAdd 699 words, FMul 784, FDiv 467, Pack 251 at 0.1.4), so a rewrite of the hot routines in assembly is the planned follow-up if size matters. Reversible: the lowerer only knows the routine names. |
| D52 | Type-name aliases | `SByte`, `SWord`, `Long` and `Dword` are read by the lexer as `ShortInt`, `Integer`, `LongInt` and `LongWord` (table `TYPE_ALIASES`); nothing after the lexer sees them, and diagnostics print the native name. The `.AsSByte` style promotions are not provided | One place to change, no effect on sema or code generation. The four names become reserved words. Reversible: delete the table. |
